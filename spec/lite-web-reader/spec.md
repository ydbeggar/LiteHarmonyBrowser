# Feature Specification: 轻鸿蒙浏览器（Lite Wearable 正文阅读浏览器）

**Created**: 2026-11-03  
**Status**: Draft  
**Input**: 用户需求：在轻鸿蒙穿戴设备（HUAWEI WATCH FIT 5 系列，408×480 矩形屏，64MB RAM / 64GB 存储，API 26.0.0，内置系统输入法）上实现网页浏览功能或类似功能，尽可能利用硬件性能；无需考虑多设备兼容性。

## Overview

轻鸿蒙浏览器是一款运行在轻鸿蒙穿戴设备（WATCH FIT 5 系列）上的**正文阅读型浏览器**。用户在手表上输入网址，应用抓取该页面，抽取标题与正文并针对 408×480 小屏重新排版分页，用户可以逐页阅读、跟随正文中的链接继续浏览、收藏与回访页面。

目标平台的系统能力不包含内嵌网页渲染引擎，因此产品不承诺"还原网页原貌"，而是把任意网页压缩为**可读、可翻页、可跳转的文本流**——这正是手腕场景下真正有价值的浏览形态：抬起手腕，看一篇文章，顺着链接往下读，看完即走。

**Why this shape**: 在 1.8 英寸屏幕上，网页原版排版（多列、浮层、广告）本身不可读；文本化 + 重新分页反而带来比手机更专注的阅读体验，同时把内存与渲染压力压到 64MB 设备可承受的范围内。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 输入网址并阅读正文 (Priority: P1)

用户抬腕打开应用，在首页点击地址栏，用系统输入法输入一个网址并确认；应用显示加载进度，随后呈现该页面的标题与第一页正文。用户上下滑动逐页阅读，直到读完全文。

**Why this priority**: 这是产品的最小闭环。没有它，其余功能都无意义；有它，产品已经可用。

**Independent Test**: 在设备上启动应用 → 输入一个可访问的网址 → 确认后能看到标题与正文第一页 → 连续翻页读到文末。全程不依赖书签、历史、设置等其它功能。

**Acceptance Scenarios**:

1. **Given** 设备已联网且用户停留在首页，**When** 用户输入一个有效网址并确认，**Then** 应用进入加载态并在抓取完成后展示该页标题与正文第 1 页，同时显示"当前页/总页数"。
2. **Given** 用户正在阅读第 1 页，**When** 用户上滑，**Then** 正文切换到下一页，页码同步更新；到最后一页时继续上滑不再产生空白页。
3. **Given** 用户正在阅读任意页，**When** 用户按返回键/点击返回，**Then** 回到首页且当前阅读进度被保留，再次进入同一网址可从上次位置继续。
4. **Given** 抓取到的页面正文极短（不足一页），**When** 展示完成，**Then** 页面只显示 1 页且不出现空白翻页。

---

### User Story 2 - 跟随正文链接继续浏览 (Priority: P2)

阅读时正文中出现的链接被集中呈现为可点选列表；用户点击其中一条，应用抓取并展示该目标页面，返回时回到上一篇文章的原有阅读位置。

**Why this priority**: 没有链接跳转，"浏览器"就退化为单篇阅读器；有了它，用户才能"逛"网页。它建立在 US1 之上，但可独立演示。

**Independent Test**: 打开一个含链接的页面 → 打开链接列表 → 选择一条 → 看到新页面正文 → 返回 → 回到原文章原页码。

**Acceptance Scenarios**:

1. **Given** 当前页面正文中至少含 1 个链接，**When** 用户打开链接面板，**Then** 列出所有可跳转链接的锚文本（锚文本缺失时以目标地址的可读形式呈现），并标注条目数量。
2. **Given** 链接面板已打开，**When** 用户点击某一条链接，**Then** 应用抓取该目标页并展示其标题与正文第 1 页。
3. **Given** 用户已从文章 A 跳转到文章 B，**When** 用户在 B 中执行返回，**Then** 回到文章 A 且恢复跳转前的页码。
4. **Given** 当前页面不含任何链接，**When** 用户打开链接面板，**Then** 显示"本页无可用链接"的空态而不是空白面板。

---

### User Story 3 - 保存书签与回访历史 (Priority: P3)

用户对一篇正在阅读的文章点"收藏"，之后可在首页的书签列表一键回到该文章；应用同时自动记录最近访问过的页面，便于快速回访。

**Why this priority**: 手表输入网址成本高，收藏与历史是"第二次打开"的关键路径，直接决定留存。

**Independent Test**: 阅读一篇文章 → 收藏 → 返回首页 → 在书签列表中找到并打开它；再检查历史列表中出现了本次访问记录。

**Acceptance Scenarios**:

1. **Given** 用户正在阅读某篇文章，**When** 用户点击收藏，**Then** 该文章以标题形式出现在首页书签列表，且按钮状态变为"已收藏"。
2. **Given** 某文章已被收藏，**When** 用户在书签列表中点击它，**Then** 直接打开该文章正文，无需重新输入网址。
3. **Given** 用户已访问过若干页面，**When** 用户查看历史列表，**Then** 按最近访问时间倒序显示，最近一条在最上方。
4. **Given** 书签或历史条目已存在，**When** 用户删除单条或清空全部，**Then** 列表立即更新且重启应用后不恢复。
5. **Given** 应用被完全关闭后重新启动，**When** 用户查看书签与历史，**Then** 内容与关闭前一致。

---

### User Story 4 - 调整阅读观感 (Priority: P4)

用户可根据环境光与个人偏好调整正文字号、行距与深浅主题（浅色/深色），设置立即生效并在下次启动时保持。

**Why this priority**: 小屏 + 强光/夜间场景下，可读性直接影响是否愿意继续用；但缺少它产品仍可用，故排 P4。

**Independent Test**: 在阅读页打开设置，切换深色主题并把字号调大 → 正文立即变化且不丢失当前页码 → 重启应用后设置仍生效。

**Acceptance Scenarios**:

1. **Given** 用户位于阅读页，**When** 用户把字号从小调到大，**Then** 正文重新分页，当前阅读位置对应的内容仍在可视范围内（不跳回第 1 页）。
2. **Given** 用户位于阅读页，**When** 用户切换深色/浅色主题，**Then** 背景与文字颜色立即切换且文字对比度足以阅读。
3. **Given** 用户已修改任一阅读设置，**When** 用户重启应用，**Then** 设置保持上次选择。

---

### User Story 5 - 无网也能演示与优雅失败 (Priority: P5)

在没有网络、目标不可达、页面无正文等情况下，应用给出明确提示与可执行动作（重试/返回/查看离线示例），而不是白屏或卡死。

**Why this priority**: 手表网络环境不稳定，失败态是高频路径；同时离线示例保证评审与演示不依赖外网。

**Independent Test**: 关闭网络后打开任意网址 → 看到失败提示与"重试"动作；点击"离线示例"能读到内置文章全文。

**Acceptance Scenarios**:

1. **Given** 设备无网络，**When** 用户请求任意网址，**Then** 在加载态结束后显示"网络不可用"提示，并提供"重试"与"返回首页"。
2. **Given** 目标页面抓取超时或返回错误，**When** 加载结束，**Then** 显示可区分的失败原因（超时/不可达/内容为空）与重试入口。
3. **Given** 页面抓取成功但未抽取到正文，**When** 展示完成，**Then** 提示"未识别到正文"并保留该页链接列表入口。
4. **Given** 设备无网络，**When** 用户从首页进入离线示例，**Then** 可完整阅读内置文章（含分页），全过程不发起网络请求。

---

### Edge Cases

- **超大页面**：单页 HTML 体量远超内存预算时，应用须截断并提示"内容过长，仅展示前 N 字"，不得崩溃或长时间无响应。
- **非 HTML 内容**：目标返回纯文本、JSON、图片或二进制时，纯文本按正文展示；其它类型给出"暂不支持该类型内容"提示。
- **纯图片/脚本渲染页面**：抽取不到正文时的处理见 US5 场景 3。
- **超长标题**：标题超过 2 行时截断显示，不挤压页码与操作区。
- **非法或不完整地址**：缺少协议头时按默认协议补全；明显非法输入立即提示，不发起请求。
- **重复请求**：加载中再次确认地址时，旧请求结果不得覆盖新请求结果。
- **系统输入法不可用**：地址输入控件无法唤起输入法时，须有可见的降级入口（提示 + 可直接使用离线示例/书签），不出现"点了没反应"的死角。
- **返回栈为空**：在首页执行返回时退出应用而非停留在空白页。
- **存储异常/写满**：书签或历史写入失败时提示但不阻塞阅读。
- **分辨率边界**：408×480 下长英文单词、连续标点、数字串不得撑破容器导致横向溢出。
- **横竖屏/圆角裁切**：矩形屏四角为圆角，页码与按钮不得贴边被裁切。

## Requirements *(mandatory)*

### Functional Requirements

**地址输入与导航**

- **FR-001**: 系统 MUST 提供地址输入入口，允许用户通过设备内置系统输入法输入网址并提交。
- **FR-002**: 系统 MUST 在提交前规范化地址：缺少协议头时补全，去除首尾空白，非法输入直接提示且不发起请求。
- **FR-003**: 系统 MUST 维护访问历史栈，支持返回上一页面并恢复其阅读位置；在首页返回时退出应用。
- **FR-004**: 系统 MUST 在一次新的请求发起后忽略此前未完成请求的结果，避免页面内容错配。

**内容获取与解析**

- **FR-005**: 系统 MUST 通过设备可用网络能力获取目标页面内容，并具备超时与失败判定。
- **FR-006**: 系统 MUST 从页面中抽取标题、正文文本与可跳转链接列表，剔除脚本、样式、导航噪声等不可读内容。
- **FR-007**: 系统 MUST 对未声明或声明错误的字符编码做合理回退，保证中文内容不出现乱码。
- **FR-008**: 系统 MUST 对超大页面做长度截断并明确告知用户，保证内存安全。

**阅读呈现**

- **FR-009**: 系统 MUST 按当前屏幕尺寸与阅读设置将正文分页，并在阅读页显示"当前页/总页数"。
- **FR-010**: 系统 MUST 支持逐页翻页，且在首页/末页边界不产生空白页。
- **FR-011**: 系统 MUST 保证正文在 408×480 屏幕上不横向溢出、不被圆角裁切。
- **FR-012**: 系统 MUST 在阅读页提供返回、收藏、链接面板、阅读设置四个入口，且入口在小屏上可点中。

**链接浏览**

- **FR-013**: 系统 MUST 以列表形式呈现当前页面的链接，锚文本缺失时以目标地址的可读形式呈现。
- **FR-014**: 系统 MUST 允许从链接列表直接打开目标页面，并将其压入历史栈。
- **FR-015**: 系统 MUST 在无链接时展示明确空态。

**数据持久化**

- **FR-016**: 系统 MUST 支持对当前文章添加/取消收藏，并在首页书签列表展示。
- **FR-017**: 系统 MUST 自动记录访问历史（标题、地址、时间），按时间倒序展示，支持删除单条与清空。
- **FR-018**: 系统 MUST 持久化书签、历史与阅读设置，应用重启后保持。
- **FR-019**: 系统 MUST 对持久化写入失败做降级处理（提示但不阻断阅读）。

**阅读设置**

- **FR-020**: 系统 MUST 支持调整正文字号与行距，调整后重新分页并保持当前阅读位置。
- **FR-021**: 系统 MUST 支持浅色/深色两套主题，并保证两套主题下的可读对比度。

**降级与演示**

- **FR-022**: 系统 MUST 提供内置离线示例文章，可在完全无网络时阅读并分页。
- **FR-023**: 系统 MUST 对无网络、超时、不可达、无正文四类失败给出可区分的提示与重试动作。
- **FR-024**: 系统 MUST 在系统输入法不可用时提供非死路的降级路径（如直接进入离线示例或书签）。

### Product Constraints (产品级约束)

- **PC-001**: 目标设备为 WATCH FIT 5 系列，屏幕 408×480 竖屏矩形（四角圆角），运行内存 64MB，存储 64GB，系统 API 版本 26.0.0。
- **PC-002**: 应用仅需在目标设备上运行，不考虑多设备/多分辨率适配。
- **PC-003**: 目标平台不提供内嵌网页渲染引擎，产品定义为正文阅读型浏览器，不承诺网页原貌还原。
- **PC-004**: 应用必须在 64MB 内存预算内稳定运行，连续阅读长文不得因内存增长而崩溃。
- **PC-005**: 应用必须利用设备已有能力（系统输入法、本地存储、网络），不引入需要后台服务的依赖。

### Key Entities

- **页面文档（Page Document）**：一次浏览的内容单元。属性：标题、来源地址、正文分段、链接列表、抓取状态（加载中/成功/失败）、失败原因。
- **链接条目（Link Item）**：正文中可跳转的目标。属性：锚文本（可空）、目标地址；归属于某个页面文档。
- **书签（Bookmark）**：用户主动保存的页面。属性：标题、地址、保存时间；与页面文档一一对应。
- **历史记录（History Entry）**：自动记录的访问。属性：标题、地址、访问时间；按时间倒序排列，可单条删除或整体清空。
- **阅读偏好（Reading Preference）**：用户的显示设置。属性：字号档位、行距档位、主题模式；全局唯一。
- **导航栈条目（Navigation Frame）**：历史栈中的一层。属性：页面文档引用、阅读页码；用于返回时恢复位置。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从打开应用到看到第一篇文章正文，用户操作不超过 3 次点击（首页 → 地址栏 → 确认）。
- **SC-002**: 常规页面从确认地址到正文可读的耗时不超过 5 秒（网络正常前提下），期间必须有可见的加载反馈。
- **SC-003**: 单页翻页响应时间不超过 300 毫秒，用户感知为"即时"。
- **SC-004**: 5 万字级长文可分页完整阅读，连续翻页 100 页无崩溃、无内存异常、无页码错乱。
- **SC-005**: 正文在 408×480 屏幕上零横向溢出、零圆角裁切；连续阅读 30 页后用户无需横向滚动。
- **SC-006**: 书签、历史、阅读设置在应用重启后 100% 保持。
- **SC-007**: 四类失败场景（无网络/超时/不可达/无正文）均能在 10 秒内给出可区分提示，且至少提供一个可执行的下一步动作。
- **SC-008**: 完全无网络环境下，用户仍能在 3 次点击内读到离线示例文章并翻页。
- **SC-009**: 应用冷启动到首页可交互不超过 3 秒。

## Assumptions

- 目标平台的网络访问能力可用；若某类地址或协议在设备上被系统限制，应用以失败态呈现并提示，而非静默卡死。
- 内嵌网页渲染引擎在目标平台不存在，因此"类似功能"按正文阅读 + 链接导航实现；这是产品定义而非降级妥协。
- 默认以竖屏 408×480 设计与分页；不考虑横屏与其它尺寸。
- 正文抽取以"可读文本"为目标，不还原图片、表格、视频与交互控件；图片型信息不在本期范围。
- 单次抓取的页面体量设定预算上限（默认不超过 200KB 源文档、不超过 5 万字正文），超出即截断并提示。
- 地址规范化默认按常用 Web 协议补全；HTTPS 优先，若目标仅支持明文则依赖系统允许范围，失败时按失败态处理。
- 书签与历史为本地数据，默认不限条数但设总量上限（默认各 100 条，超出淘汰最旧），无隐私加密需求。
- 阅读偏好默认：中等字号、标准行距、浅色主题。
- 应用界面语言为简体中文，不提供多语言。
- 自动化验证在 Lite Wearable 模拟器上完成（构建 + 安装 + 主流程 UI），真机 FIT 5 系列由用户人工完成最终验收；真机安装使用签名后的安装包，通过手机侧调测工具完成（平台不支持无线调试）。
- 系统输入法仅在真机可用；模拟器上地址输入无法唤起输入法属于平台限制，验证时以离线示例与直接打开已存条目覆盖主流程。

## Open Questions

- 首页除地址入口、书签/历史摘要、离线示例外，是否需要"最近阅读"直达卡片？（默认：提供最近一次阅读的直达入口）
- 历史记录是否需要按站点聚合展示？（默认：不做聚合，纯时间倒序）
- 是否需要"分享/复制地址"能力？（默认：本期不做）
